ПОГОНЯ — ГДЕ ПОСМОТРЕТЬ И ОБЪЯСНИТЬ МЕХАНИКИ

Быстрый способ: при закрытом Unreal запустите OpenBlueprints.cmd из папки проекта.
Откроются графы жизней, интерфейса и начала раунда.
Если редактор уже открыт, используйте путь через Content Drawer ниже.

Откройте Pogonya.uproject. Внизу нажмите Content Drawer (Ctrl+Space).
Перейдите в Content → Pogonya → Blueprints.
Дважды нажмите нужный BP. Слева откройте My Blueprint → Graphs.
Если панель скрыта: Window → My Blueprint.
Граф открывается двойным щелчком. Узлы соединены линиями: белые линии показывают порядок действий.
Для поиска внутри Blueprint нажмите Ctrl+F и введите имя события или переменной.
Дважды нажмите найденный результат. Если узлы мелкие, приблизьте их колесом мыши.
Изменения сохраняются кнопками Compile и Save.

1. ГДЕ ЗАДАНЫ ТРИ ЖИЗНИ
BP_PogonyaCharacter → переменная Lives → Default Value = 3.
BP_PogonyaGameMode → граф 02_Start_Round → событие StartRound → узел Set Lives со значением 3.
StartRound выдаёт три жизни каждому при начале и перезапуске раунда.
Если менять начальное число жизней, надо согласованно изменить обе эти настройки и три индикатора HUD.

2. ЧЕРЕЗ КАКУЮ ФУНКЦИЮ УМЕНЬШАЮТСЯ ЖИЗНИ
BP_PogonyaCharacter → граф 05_Three_Lives_and_Death.
Начало цепочки — пользовательское событие GraphReceiveHit.
Проверяется время после прошлого попадания. Потом вычисляется Lives - 1, и Set Lives сохраняет результат.
Если Lives <= 0, устанавливается bOut = true: игрок выбыл.
Персонаж останавливается, меняет позу и больше не может двигаться или подбирать предметы.
Если у него был ключ, SpawnActor создаёт ключ рядом, а bKey становится false.
На защите: «Жизни хранятся в переменной Lives. При попадании событие GraphReceiveHit уменьшает её на единицу. При нуле персонаж выбывает».

3. КАК ПОДБИРАЮТСЯ ПАЛКА И КЛЮЧ
BP_PogonyaCharacter → 00_Input_and_Network: InputAction Interact (клавиша E) вызывает GraphInteract.
BP_PogonyaCharacter → 03_Pickups_and_Escape: здесь находится сама цепочка GraphInteract.
Сервер проверяет, что раунд начался, не закончился и игрок не выбыл.
Get All Actors Of Class находит предметы BP_PogonyaPickup. Цикл перебирает их.
Get Distance To проверяет расстояние: предмет должен быть ближе PickupRange (190 см).
bHunter означает роль гонщика. У предмета bKey = true означает ключ, false — палку.
Гонщик может получить только палку; беглец — только ключ.
Set bStick или Set bKey запоминает предмет у персонажа. Destroy Actor убирает подобранный предмет с карты.
На защите: «Нажимаем E. Игра проверяет расстояние и роль, записывает предмет в состояние персонажа и удаляет его с земли».

4. КАК РАБОТАЕТ УДАР
BP_PogonyaCharacter → 04_Stick_Attack → GraphAttack.
Сначала проверяется роль, палка и задержка между взмахами.
Потом ищется живой беглец: он должен находиться рядом и перед гонщиком.
Line Trace проверяет, нет ли между ними стены. При допустимом попадании вызывается GraphReceiveHit у беглеца.
AttackRange = 180 см; AttackCooldown = 0,8 с; HitInvulnerability = 1,2 с.
Эти параметры доступны в Class Defaults персонажа.

5. ГДЕ ВЫВОДИТСЯ «ВЫ — ГОНЩИК» И «ВЫ — БЕГЛЕЦ»
BP_PogonyaHUD → 01_Draw_Interface → событие ReceiveDrawHUD.
Get Owning Pawn получает нашего персонажа. Его переменная bHunter выбирает текст через Select.
Узел Draw Text рисует выбранную надпись на экране.
Lives определяет число и цвет трёх полосок. Draw Rect рисует полоски, Draw Text — число жизней.
Таймер, число спасшихся и результат читаются из BP_PogonyaGameState.
Здесь же нарисованы подсказки E, экран результата и красная вспышка при попадании.
Для быстрого поиска: Ctrl+F → «ВЫ» или «Draw Text».
На защите: «Интерфейс находится в BP_PogonyaHUD. Он читает роль и жизни персонажа и выводит текст и три индикатора».

6. КАК ОТКРЫВАЮТСЯ ВОРОТА И ПРОИСХОДИТ ПОБЕГ
BP_PogonyaCharacter → 03_Pickups_and_Escape: E возле выхода проверяет ключ.
Если ключ есть, в GameState устанавливается bGateOpen = true.
BP_PogonyaGate → 01_Open_Gate_Animation читает эту переменную.
FInterpTo плавно меняет OpenAmount от 0 к 1, а Set Relative Location раздвигает створки.
Убежавшему персонажу задаются bEscaped = true и bOut = true; счётчик Escaped увеличивается.
После открытия другие беглецы тоже могут нажать E у выхода, даже без ключа.
В новом раунде bGateOpen сбрасывается, и створки закрываются.

7. ГДЕ ВЫБИРАЕТСЯ ГОНЩИК И ЗАПУСКАЕТСЯ РАУНД
BP_PogonyaGameMode → 02_Start_Round → StartRound.
Состав дополняется ботами до четырёх. Random Integer in Range выбирает индекс одного гонщика.
Цикл задаёт bHunter для выбранного персонажа и сбрасывает жизни и предметы всех игроков.
Ключ и палка появляются в двух разных случайных тайниках.
01_Lobby_and_Timer: 8 секунд ожидания, затем 360 секунд игры.
03_Resolve_Round: проверка оставшихся беглецов, гонщика и времени; выбор победителя.
BP_PogonyaController → 01_Restart_Request: R вызывает серверное событие ServerRestartRound.

8. КАК РАБОТАЮТ БОТЫ
BP_PogonyaCharacter → 09_Bot_Decision: выбор цели — предмет, противник или выход.
10_Bot_Steering: проверка восьми направлений сферическими трассировками и движение по свободному направлению.
08_Tick_and_Animation: запуск решений и процедурное движение рук, ног и палки.
Это простой обход препятствий, без полноценного поиска пути по NavMesh.

9. ГДЕ МОДЕЛЬ ПЕРСОНАЖА
BP_PogonyaCharacter → Viewport и панель Components.
Body, Hood, Mask, руки, ноги, рюкзак и Weapon — отдельные редактируемые компоненты.
Blender-файлы из предыдущей работы сохранены в папке Blender проекта.

Все перечисленные механики сейчас исполняются в Blueprint. Новые BP наследуются от стандартных классов Unreal.
Старые BP_ChaseCharacter и C++ ChaseGame оставлены как прежняя версия; действующая карта использует BP_PogonyaGameMode.
Для обычного изменения механик редактируйте новые BP в Content/Pogonya/Blueprints, а не старую папку Characters.
